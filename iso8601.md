## Dates
<!-- {: .-three-column} -->

### Calendar dates

```
2026-11-23          # extended
20261123            # basic
2026-11             # month precision
2026                # year precision
```

Extended dates use `-`; basic dates omit separators. Reduced precision is allowed for months and years.

See: [ISO 8601-1:2019](https://www.iso.org/standard/70907.html)

### Week dates

```
2026-W48-1          # Monday of week 48
2026W481            # basic
2026-W48            # week without day
```

Week 01 contains the first Thursday, so the week-year can differ from the calendar year.

See: [ISO 8601-1:2019](https://www.iso.org/standard/70907.html)

### Ordinal dates

```
2026-327            # day 327 of 2026
2026-327T10:30Z     # with a time
```

Day numbers run from 001 to 365, or 366 in leap years. "Julian date" is a misleading name for this form.

See: [ISO 8601-1:2019](https://www.iso.org/standard/70907.html)

## Times
<!-- {: .-three-column} -->

### Time of day

```
10:30               # hour and minute
10:30:00            # with seconds
T103000             # basic
24:00:00            # end of day
```

`24:00:00` is the end of a day in ISO 8601-1:2019/Amd 1:2022; RFC 3339 excludes it.

See: [RFC 3339 §5.7](https://www.rfc-editor.org/rfc/rfc3339#section-5.7)

### Fractional seconds

```
10:30:00.123        # dot
10:30:00,123        # comma
```

The fraction applies to the smallest unit present. ISO 8601 allows either mark; RFC 3339 uses the dot.

See: [RFC 3339 §5.6](https://www.rfc-editor.org/rfc/rfc3339#section-5.6)

### UTC and offsets

```
10:30:00Z           # UTC
10:30:00+02:00      # two hours ahead
10:30:00-05:00      # five hours behind
10:30:00+0000       # basic offset
```

`Z` means `+00:00`. An offset is local time minus UTC; lowercase `t` and `z` are also accepted.

See: [RFC 3339 §4.2](https://www.rfc-editor.org/rfc/rfc3339#section-4.2)

### Date and time

```
2026-11-23T10:30:00Z
2026-11-23T10:30:00+02:00
2026-11-23T10:30:00.123Z
```

`T` separates the date and time. RFC 3339 requires a full date, full seconds and an explicit offset.

See: [RFC 3339 §5.6](https://www.rfc-editor.org/rfc/rfc3339#section-5.6)

### Sorting

```
2026-11-23T08:30:00Z
2026-11-23T10:30:00Z
2026-11-24T00:15:00Z
```

Fixed-width UTC strings sort chronologically as plain text, as long as offsets and fractional precision match.

See: [RFC 3339 §5.1](https://www.rfc-editor.org/rfc/rfc3339#section-5.1)

## Durations and intervals
<!-- {: .-three-column} -->

### Duration

```
P1Y2M3D             # years, months, days
PT1H30M             # hours and minutes
P2W                 # two weeks
PT0.5S              # half a second
```

`P` starts a duration; `T` separates date and time parts. `P1M` is one month, while `PT1M` is one minute.

See: [ISO 8601-1:2019](https://www.iso.org/standard/70907.html)

### Designators

| Token | Meaning |
| --- | --- |
| `Y` | years |
| `M` | months before `T` |
| `D` | days |
| `H` | hours after `T` |
| `M` | minutes after `T` |
| `S` | seconds after `T` |

Zero values may be omitted, but at least one field is required: `PT0S` is valid, `P` is not.

See: [ISO 8601-1:2019](https://www.iso.org/standard/70907.html)

### Intervals

```
2026-11-23T10:30Z/2026-11-23T12:00Z
2026-11-23T10:30Z/PT90M
PT90M/2026-11-23T12:00Z
2026-11-23/11-24
```

A slash separates start and end. Omitted end fields are copied from the start, so `/11-24` keeps the year.

See: [ISO 8601-1:2019](https://www.iso.org/standard/70907.html)

### Repeating intervals

```
R3/2026-11-23T10:00Z/PT1H
R/2026-11-23T10:00Z/PT1H
R0/2026-11-23T10:00Z/PT1H
```

`R3` means three occurrences, bare `R` repeats indefinitely, and `R0` means none.

See: [ISO 8601-1:2019](https://www.iso.org/standard/70907.html)

## In code

### JavaScript

```js
new Date('2026-11-23T10:30:00+02:00')
  .toISOString()  // '2026-11-23T08:30:00.000Z'
```

`Date` parses extended date-times; date-only strings are treated as UTC, and week or ordinal dates are not parsed.

See: [Date.parse](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/parse)

### Python

```python
from datetime import datetime
dt = datetime.fromisoformat('2026-11-23T10:30:00+00:00')
dt.isoformat()  # '2026-11-23T10:30:00+00:00'
```

`fromisoformat()` accepts extended forms and offsets. Weeks use `date.fromisocalendar()`, ordinals use `strptime('%Y-%j')`.

See: [datetime.fromisoformat](https://docs.python.org/3/library/datetime.html#datetime.datetime.fromisoformat)

### Unix date

```bash
date -u -d '2026-11-23T10:30:00Z' '+%Y-%m-%dT%H:%M:%SZ'
# 2026-11-23T10:30:00Z
```

GNU `date` parses ISO timestamps and converts them with `%s` and `@<seconds>`.

See: [date(1)](https://www.gnu.org/software/coreutils/manual/html_node/date-invocation.html)
